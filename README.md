# 基石数据库（jishi 版）

用**纯基石语言**实现的嵌入式数据库引擎，完全替换内置 `数据库` 模块。
对外 API 与内置模块**同名、同参、同报错**——换一行导入即可切换：

```jishi
导入 基石数据库 从 本地包 为 数据库     # 本引擎（0.4.0）
# 导入 数据库                          # 内置模块（0.3.5 起 = 本项目 0.1.0 的内置版）
```

当前版本 **0.4.0**，建议基石语言 **0.3.6**（最低 0.3.4 可跑：新语言能力按惰性探测
自动启用，缺了就回退旧路径——0.3.5 的 `排序按比较`/`内建.打开` 持久文件柄、
0.3.6 的列表字典序比较（多键元组排序快路）都是自动启用）。

> **兼容基线说明**：jishi 0.3.5 的内置 `数据库` 模块就是本项目 **0.1.0** 的内置版
> （不再是 rusqlite）。所以「与内置对拍」= 保证从内置 0.1.0 平滑升级到本引擎；
> 真 SQLite（C 内核 3.50.4）作为远期性能标杆，对照工具见下文「性能对比」。

## 快速开始

```jishi
导入 基石数据库 从 本地包 为 数据库

令 库 = 数据库.打开("账本.db")
数据库.建表(库, "账目", ["日期", "事由", "金额"])
数据库.插入(库, "账目", {"日期": "2026-11-01", "事由": "工资", "金额": 8000})
数据库.建索引(库, "账目", ["日期"])
遍历 行 在 数据库.查询(库, "账目", {"金额": {">": 0}}):
    打印(行["事由"])
数据库.关闭(库)
```

包目录：`基石数据库/`（把本目录放进项目的 `.jishi/packages/` 下，或建 junction：
`mklink /J .jishi\packages\基石数据库 基石数据库`，仓库自带 `.jishi/` 但已 gitignore）。
脚本的工作目录必须能找到 `.jishi/packages/`。

## 21 个 API（与内置一致）

| 函数 | 说明 |
|---|---|
| `打开(路径)` / `关闭(库)` | 句柄是路径文本；空路径 `""` = 私有临时库（不落盘） |
| `表们(库)` / `有表(库, 表名)` | |
| `建表(库, 表名, 字段们)` | 字段名列表；`id` 是隐含自增列 |
| `建索引(库, 表名, 字段们, 唯一=假)` | 唯一索引做约束检查；非唯一索引加速等值**与范围**查询 |
| `插入(库, 表名, 记录)` / `批量插入(库, 表名, 记录们)` | 批量 = 一条日志 = 一个事务 |
| `修改(库, 表名, 条件, 新值)` / `删除(库, 表名, 条件)` | 条件不能为空；语句级唯一冲突整句原子 |
| `查询(库, 表名, 条件=空, 排序=空, 倒序=假, 条数=空)` | 条件用嵌套字典：`{"金额": {">": 0}}` |
| `条数(库, 表名, 条件=空)` | |
| `汇总(库, 表名, 按, 求和, 条件=空)` | 按/求和都是单字段名 |
| `执行(库, SQL, 参数们=空)` / `执行查询(库, SQL, 参数们=空)` | SQL 逃生口（见下） |
| `开始(库)` / `提交(库)` / `回滚(库)` | 事务：内存可见、提交一次落日志、回滚恢复备份 |
| `用事务(库, 动作)` | 动作跑完自动提交，抛错自动回滚并重抛原错误 |
| `迁移(库, 目录)` | 按文件名序跑目录里的 `.sql`，`schema_版本` 表记账，跑过的不重跑 |
| `查询到表格(库, SQL, 参数们=空)` | SELECT 直接返回 `表格` 值（表头 + 数据行，空单元格 → ""） |

条件运算符只有 `> < >= <= != 包含 非空`；`{"字段": 空}` 永不匹配（NULL 语义），
`{"非空": 真/假}` 取非空/取空。

事务语义与内置逐字对齐（63 项对拍）：嵌套开始/无事务提交/回滚报同款值错误；
语句级报错不关事务；关闭时未提交改动丢弃；事务期间不紧凑。

## SQL 子集（v1）

```
SELECT 列们 FROM 表 [WHERE …] [GROUP BY 列] [HAVING 表达式] [ORDER BY 列 [ASC|DESC], …] [LIMIT n]
INSERT INTO 表 [(列,…)] VALUES (…,…) [, (…,…)…]
UPDATE 表 SET 列 = 表达式 [,…] [WHERE …]
DELETE FROM 表 [WHERE …]
CREATE TABLE 表 (列 [,…])        DROP TABLE 表 [IF EXISTS]
ALTER TABLE 表 ADD [COLUMN] 列   -- 旧行补空；返回 1
```

- 表达式：比较（`= == != <> < > <= >= LIKE IN`）、`IS [NOT] NULL`、`AND/OR/NOT`、括号、算术
- 聚合：`COUNT(*)` / `COUNT(列)` / **`SUM` / `AVG` / `MIN` / `MAX`**（0.3.0 新增，
  SQLite 语义：空组给空、SUM 全整数给整数、AVG 恒实数、MIN/MAX 按类型序）`[AS 别名]`；
  输出键保留原文写法（`SUM(额)` 就叫 `SUM(额)`）
- **HAVING**（0.4.0 新增，内置不支持）：GROUP BY 后组过滤，条件里可用聚合调用与分组列，
  SQLite 语义（如 `HAVING COUNT(*) > 1 AND SUM(额) < 100`）；无 GROUP BY 时对全表聚合行过滤
- `?` 参数按语句就地重编；标识符大小写不敏感；反引号/双引号/方括号包裹原样取
- `id` 是隐含第一列：SELECT/WHERE/ORDER BY/UPDATE 都能用
- **WHERE 走索引**（0.3.0 等值/范围，0.4.0 加 IN 与 LIKE）：纯 AND 链、每项「列
  (= < > <= >= 常量)」复用索引等值/范围加速（10 万行 SQL 范围计数 0.23s → 4.6ms/次）；
  `列 IN (常量…)` 逐值查索引取并集；`列 LIKE 'abc%'`（及无通配符形态）走有序表
  范围扫——候选是超集，结果与全表扫逐字一致（22 项对拍）；其余形态全表扫
- 不在子集里的语法 → 运行期错误，消息为中文说明

## 存储与并发

- `<库路径>` = 快照（首行格式头 + JSON）；`<库路径>.log` = 追加日志（JSONL，每次写一条）
- 日志走**持久文件柄快路径**（语言 0.3.5 的 `内建.打开`，引擎双通道探测自动启用；
  IO 比逐次追加快 43 倍，逐行插入 1 万 3.9s→1.8s）
- 打开时重放日志（改行重放走 id 字典，O(行+改)）；只删 `.db` 留下孤儿日志 → 打开自动清掉
  （与内置 M212 语义一致）
- 关闭时/日志超 4096 行时自动紧凑（合并写回）；事务内写操作只缓冲，提交一批落日志
- 崩溃恢复：尾部残行丢弃重写；中间坏行如实报错
- 锁文件 `<库路径>.lock` 防多进程同时写；崩溃留残锁 → 删掉 `.lock` 即可（报错消息会说明）
- 字节值以 `{"$字节": "<base64>"}` 存盘（JSON 没有二进制）

## 性能对比（远期标杆）

`tools/对比基准.jsh` 一条命令跑四腿对照（约 3 分钟，数字落 JSON，控制台出表）：
**本引擎 vs 内置 0.1.0 vs SQLite(C, CPython sqlite3) vs rusqlite**（同一 SQLite C 内核）。

```
jishi tools/对比基准.jsh
```

rusqlite 腿需要编译一次基准程序（bundled SQLite 随包编译）：

```
cargo new "%TEMP%\jsdb_rusqlite_bench" --bin --name rusqlite_bench
copy tools\rusqlite基准.rs "%TEMP%\jsdb_rusqlite_bench\src\main.rs"
cd /d "%TEMP%\jsdb_rusqlite_bench" && cargo add rusqlite --features bundled && cargo build --release
```

（Rust 工具链是 GNU 目标时需要 C 编译器，如 w64devkit；MSVC 目标需要 VS Build Tools。）
sqlite3(C) 腿免编译，直接用（CPython 自带 SQLite 3.50.4）。

2026-11-22 复跑（语言 0.3.6）：与内置 0.1.0 相比 16 项中 15 项持平或更快
（范围加速 60 倍、SQL COUNT 9 倍、事务 5 倍、重开 40 倍）；与 SQLite 的差距 7~155 倍，
逐项目标见 `功能路线图.md`。完整表随 `tools/对比基准.jsh` 输出。

压力测试（`tests/压力_test.jsh`，10 万行，±20% 浮动）：批量插入 1.5s、
索引等值 0.04ms/次、范围索引缓存后 2.9ms/次（~230 倍）、SQL WHERE 走索引 4.6ms/次、
多键同型排序（纯排序部分）2 万 0.02s（0.4.0 元组快路，16 倍；混型/降序 0.36s）、
关闭紧凑 0.66s、重开 1.3s。

## 工具（`tools/`）

```
jishi tools/工具箱.jsh 看表   <库路径>
jishi tools/工具箱.jsh 看记录 <库路径> <表名> [条数=10]
jishi tools/工具箱.jsh 统计   <库路径> <表名>
jishi tools/工具箱.jsh 导出CSV <库路径> <表名> <CSV路径>
jishi tools/工具箱.jsh 导入CSV <库路径> <表名> <CSV路径> [编码=auto]
jishi tools/工具箱.jsh 备份   <库路径> <备份路径>
jishi tools/工具箱.jsh 恢复   <备份路径> <库路径>

jishi tools/迁移.jsh <SQLite库路径> <目标路径>   # SQLite → 基石格式（python 子进程读真 SQLite；rowid 保号，BLOB 原样）
jishi tools/基准.jsh                              # 可复跑性能基准（2 万行快速版）
jishi tools/对比基准.jsh                          # 四腿性能对比（见上）
jishi tools/自检.jsh                              # 换机器环境自检
```

CSV 按 RFC 4180（引号包裹、内部引号双写、字段内换行）；空单元格 → 空；纯数字 → 整数/小数。
导入编码 `auto` = 先严格试 UTF-8，失败按 GBK（国内老 CSV 常见）；也可明说 `utf-8` 或 `gbk`。

## 兼容性

对拍测试是硬保证：同一批用例分别喂内置模块（0.3.5 = 本项目 0.1.0 内置版）与本引擎，
返回值 JSON 与报错类型/消息逐项比较。
**有意偏差 7 项**（对拍中标「偏差」不计失败）：

1. 插入空记录：内置报错误原文，引擎报中文值错误
2. SQL 报错消息：内置给错误原文 + `at offset N` 后缀，引擎给简洁版（语义错同款英文，语法错中文说明）

**超出内置 0.1.0 的增强**（内置不支持、无法对拍，语义按 SQLite 标准实现并以冒烟断言）：
SQL 聚合 `SUM/AVG/MIN/MAX`、SQL HAVING、SQL WHERE 的 `>=`/`<=`、WHERE 索引加速
（等值/范围/IN/LIKE 前缀）、孤儿日志清理（内置 M212 行为对齐）。

## 已知语言坑（详见 `语言问题清单.md`，均有最小复现；0.3.6 复测结论在清单顶部）

- 逻辑运算符只有 `与 或 非`（`且` 是解析期错；0.3.6 起报错会点名「且」）
- `类/次/是/当/为/从` 等单字是关键字，命名要避开
- 反引号模板串里 `{` 是插值起点（JSON 字面量用 `字符(34)` 拼）
- 包内所有模块顶层拼接成**一个函数作用域**：门面函数名会遮掉内建裸名（如 `打开`），
  且加载期顶层变量对函数体不可见——共享状态用字典 + 惰性初始化（详见清单 F 节）
- ~~嵌套具名函数体一旦出现 `catch` 块，捕获失效~~ **0.3.6 已修**（共享状态传参仍是最稳写法）
- **`系统.执行` 不解析 argv 引号**（0.3.5 实测 N6，0.3.6 未修）：引号原样进参数——外部命令
  一律裸参数/环境变量传参/代码落盘（`迁移.jsh` 与 `对比基准.jsh` 是范例）
- ~~字典「在」未命中线性扫描~~、~~报错行号错标~~ **0.3.4 已修**；
  ~~A2 无 nonlocal~~ **0.3.5 已修**（`全局` 声明）；~~A4 匿名函数文档矛盾~~ **0.3.5 已修**；
